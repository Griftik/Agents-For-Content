# Архитектура данных и синхронизации

> Как роли (человек, Claude, агенты) и хранилища (Obsidian-vault на Google Drive,
> сервер, git) работают вместе **синхронно и без конфликтов**.
> Расширяет «Архитектурное решение №1 (гибрид)» из опорного документа.

## Главный принцип: один писатель на данные

Каждый тип данных имеет **ровно одного писателя**; все остальные — только читают.
Где нужны и агент, и человек — работает **handoff «предложено → утверждено»**.
Так синхронизация не конфликтует в принципе (никто не пишет один файл вдвоём).

## Три хранилища

| Хранилище | Что держит | Кто смотрит |
|---|---|---|
| **Obsidian-vault** (папка на Google Drive) | «ЦЕННОЕ» человеко-читаемое: скилы (копия), дайджесты, контент-план, аналитика, партнёры, боли встреч, идеи | Женя (Obsidian), Claude (коннектор Drive), агенты (rclone) |
| **Сервер** | «РАБОЧЕЕ»: очередь публикаций, состояния постов, кэш, локальные копии зон | только агенты |
| **git-репозиторий** | Код + **скилы** (версионируются, ревью) | Claude, Женя, сервер (`git pull`) |

Плюс `_data/` внутри vault — машинные JSON (`posts_for_claude.json`, метрики):
ценные, но не «заметки». Пишут агенты, руками не редактируем.

## Роли и доступ

- **👤 Женя** — через Obsidian поверх vault на Drive. Правит свои зоны, утверждает
  план и питчи, диктует идеи Контентщику (через бота, не через vault).
- **🤖 Claude** — через коннектор Google Drive (vault) + git (код/скилы).
  Держит скилы в git и зеркалит их в vault для просмотра.
- **⚙️ Агенты** (на сервере) — headless. Через rclone тянут свои read-зоны и
  выкладывают свою write-зону.

## Раскладка vault (зоны = владельцы)

```
Фабрика/                     (Obsidian-vault, на Google Drive)
├── 00_Скилы/                копия из git (positioning, style, multiplier…) — только чтение
├── 10_Дайджесты/            пишет Исследователь; Женя читает/помечает
├── 20_Контент-план/
│   ├── предложено/          пишет Стратег
│   └── утверждено/          утверждает Женя  ← агенты берут ТОЛЬКО отсюда
├── 30_Аналитика/            пишет Аналитик; Женя читает
├── 40_Партнёры/
│   ├── предложено/          пишет Разведчик (каналы, питчи)
│   └── одобрено/            Женя одобряет отправку
├── 50_Боли-встреч/          сырьё для тем встреч (append-заметки)
├── _Входящее/               только Женя (сырые мысли, идеи)
└── _data/                   машинные JSON (posts_for_claude, метрики) — не редактируем руками
```

## Скилы: где правда

- **Каноничны в git** (версионирование + ревью + прямой доступ Claude).
- **Зеркалятся в `00_Скилы`** vault — Женя их видит в Obsidian.
- Правка скила — через Claude/чат (или прямой PR). Один писатель = git → без конфликтов.
- *(Если захочешь править скилы прямо в Obsidian — сделаем vault каноничным, а git —
  зеркалом. Тогда меняем направление синка для `00_Скилы`. По умолчанию — как выше.)*

## Карта ввода-вывода агентов

| Агент | Читает | Пишет (его зона) |
|---|---|---|
| Стратег | 30_Аналитика, 40_Партнёры/одобрено, 00_Скилы | 20_Контент-план/**предложено** |
| Исследователь | 20/утверждено, 50_Боли, 00_Скилы | 10_Дайджесты |
| Контентщик | 10_Дайджесты, надиктовка Жени (бот), 00_Скилы | публикация в TG, запись поста → `_data` |
| Мультипликатор | пост, 00_Скилы (multiplier) | версии под площадки → сервер/`_data` |
| Публикатор | версии | публикации + лог → `_data` |
| Аналитик | метрики площадок, `_data/posts` | 30_Аналитика, обновляет `_data/posts_for_claude.json` |
| Разведчик | ниша, конкуренты | 40_Партнёры/**предложено** |
| 👤 Женя | дайджесты, аналитика | утверждает 20 и 40, пишет 50 и _Входящее |

## Правила синхронизации (rclone на сервере)

1. **PULL:** агент тянет свои read-зоны (скилы, `утверждено/`, `_data`) Drive → локально.
2. **PUSH:** агент выкладывает **только свою** write-зону локально → Drive.
   Один писатель на зону ⇒ push никогда не конфликтует.
3. **Handoff:** агент пишет в `предложено/`; Женя переносит/правит в `утверждено/`
   (или `одобрено/`); агенты читают только утверждённое.
4. **Рабочее** (очередь, состояния постов) — на сервере, в vault НЕ тащим
   (быстро меняется, человеку не нужно).
5. **Частота:** после значимого изменения + по расписанию (напр. Аналитик — раз в 2 дня).

## Что НЕ кладём в vault

- Очередь публикаций и состояния постов «в полёте» — сервер.
- Секреты (`.env`, токены) — только сервер.
- Сырые технические логи — сервер.
