# Отчёт симуляции пользователей — «Успею» (приложение, версия 2)

Прогон: seed `20261024`, 50 персон (занятой 6, интеллектуал 7, мастер 3, нетворкер 6, родитель 5, спортсмен 5, тусовщик 6, экономный 5, эстет 7), неделя онбординга и 4 недели после неё, 3913 вызовов API через FastAPI TestClient. События: seed 177 шт.

Команда: `python -m leisure.sim.runner --users 50 --weeks 4 --seed 20261024`. База `leisure_sim` создаётся и удаляется прогоном, база разработки не затрагивается. Один seed — один и тот же отчёт (кроме строки о длительности в конце).

> **Как читать.** Код продукта — настоящий: API, лента, скоринг, обучение, приглашения, БД. Люди — модель: когда открыть приложение, какой день и направление выбрать, нажать ли «Иду», сколько терпеть онбординг (`personas.py`, `app/driver.py`). Абсолютные доли — «что будет при таком поведении»; надёжны находки о механике: дефекты и наблюдения ниже подтверждены журналом вызовов.

## 3. Дефекты продукта

### 3.1 Открытые

### Д1 [средняя] Три «сходил, 5» не поднимают категорию в ленте профиля

- Проб 1, поднялась в 0 (ещё 3 не оценить: после отметок событий категории в ленте не осталось). Сравнение с «двойником» (тот же профиль без этих решений): Концерты: профиль ['Театр', 'Театр', 'Театр', 'Концерты', 'Концерты'], двойник ['Театр', 'Театр', 'Театр', 'Концерты', 'Концерты']
- Баллы первых карточек: профиль [('Театр', 93), ('Театр', 87), ('Театр', 80), ('Концерты', 79), ('Концерты', 78)], двойник [('Театр', 81), ('Театр', 75), ('Театр', 68), ('Концерты', 67), ('Концерты', 66)]
- **Где:** leisure/core/affinity.py (decision_weights «сходил», rating_scale), leisure/core/feed.py
- **Как воспроизвести:** «Иду» на три события категории вне пятёрки, после даты — «сходил» с оценкой 5, сравнить GET /api/feed с профилем-двойником.

### Д2 [средняя] Метрики роста API расходятся с формулами GROWTH.md §4

- Не совпали: Доля «иду» с приглашением, Совместные походы.
- Доля «иду» с приглашением: симулятор 15,6 % (99 из 633), API 56,6 % (99 из 175).
- Совместные походы: симулятор 11,1 % (70 из 633), API 40,0 % (70 из 175).
- В версии 2 «иду» после даты события превращается в «сходил» / «не сходил»: сейчас в БД «иду» 175, а «иду» когда-либо — 633. `growth_metrics` делит на текущие «иду», поэтому доля «иду» с приглашением и совместные походы растут по мере отметок в плане; симулятор делит на «иду» когда-либо.
- **Где:** leisure/api/invites.py (growth_metrics: going)
- **Как воспроизвести:** Отметить «сходил» несколько «иду» и сравнить GET /api/metrics/growth до и после.

## 4. Наблюдения и юзабилити (по убыванию важности)

### У1. Предложенные восемь направлений слабо совпадают с тем, что хочет человек

- Из восьми в интерес персоны попало в среднем 3,0 (38 %); правок в медиане 4.
- **Что сделать:** Ранжировать направления по ценностям точнее.

### У2. «Освободился вечер»: в будний вечер «Сегодня» часто пусто

- Из 132 вечерних открытий лента «Сегодня» была пустой в 95 (72 %); в 40 человек переключился на «Завтра». В seed события по будням редки (после первого уикенда 4–18 событий на неделю).
- **Что сделать:** Пока база бедна, показывать в «Сегодня» ближайшие дни с подписью «Завтра» и «Послезавтра», а не пустой экран.

### У3. Пустая лента

- Из 700 открытий лента пуста в 195 (28 %); по дням: Неделя — 198, Сегодня — 354, Завтра — 148.
- **Что сделать:** Коллекторы: больше событий по будням; интерфейс: предлагать другой день, а не пустоту.

## 5. Рост через друзей (docs/GROWTH.md)

Граф дружбы: у каждой из 50 персон 2–5 друзей (в среднем 3,7), из них 80 внутри сервиса и 103 вне его (новые персоны близкого, но другого архетипа). После «иду» персона зовёт друга с вероятностью от общительности и от того, подходит ли событие другу; друг принимает с вероятностью от скоринга события под его скрытый вкус. Всё через API приложения: `POST /api/invites`, у друга — гостевая сессия, `GET /api/invites/{code}`, `POST …/open`, `POST …/accept` (согласие при первом касании), затем предложение онбординга и `PUT /api/profile`. «Имя идёт с тобой» пригласивший видит в плане (`companions`), момент рекомендации — `ref_ask` в ответе на оценку 4–5. Гости в основные метрики п. 11 не входят.

## 7. Ограничения прогона

- Поведение людей — допущения (`leisure/sim/personas.py`, `app/driver.py`, `app/social.py`): частота открытий 1–5 в неделю по вовлечённости, чаще вечером четверга и пятницы; выбор дня по характеру (спонтанные — «Сегодня», планирующие — «Неделя»), направление «Дело» чаще у нетворкеров и занятых; вероятности «Иду» / «Не моё», оценок, ухода. Другие допущения дадут другие доли.
- Нажатия считаются на клиенте по схеме FLOW-ONBOARDING и экранам v2 (свайп мимо карточки = 1); на сервер уходят только вызовы API.
- Seed — 177 событий, почти все на первом уикенде; по будням событий мало, поэтому «Сегодня» вечером часто пусто — это ограничение базы, а не ленты.
- Часы: `services.utcnow` и `datetime.now()` в модулях профилей и приглашений подменены часами симуляции, `created_at`/`updated_at` в БД — триггерами; окно «сегодня» в ленте считается по ним.
- Удержание — доля открывших приложение за неделю; открытия запланированы по характеру и прекращаются только при уходе (вовлечённость ниже порога), поэтому доля высока по построению.
- Не проверялись: веб-клиент (Next.js), установка PWA, системный «Поделиться», почта (magic link), параллельные запросы, несколько городов.
