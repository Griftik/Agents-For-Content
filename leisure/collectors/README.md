# Коллекторы: статус источников

Источники — из `seed/sources.json` (реестр, версия 2). Интерфейс один: модуль `collectors/<name>.py`, класс-наследник `Collector`,
метод `collect(city, date_from, date_to) -> list[RawEvent]`, регистрация декоратором `@register`.
Порядок предпочтения: API, затем RSS, затем разметка. Ошибки источника — `CollectorError` (`base.py`).

Проверки сети сделаны 2026-10-24 из окружения разработки (облачный контейнер, исходящий трафик через прокси): GET с
идентифицирующим User-Agent, таймаут 10 с, пауза 1 с между запросами к одному хосту. Часть хостов отвечает нестабильно
(обрывы, 502 прокси): такие проверялись трижды, в реестр попало только то, что ответило хотя бы раз.

## Реестр источников

Всего **131** записей: агрегаторы и билетные операторы 18, площадки 37, образование, бизнес и спорт 11, клубы 6, медиа 13, Telegram-каналы 46.
Без ключа сейчас доступны **111** (71 сайтов и 40 каналов): ответили 2xx с этого хоста, ключ не нужен, robots.txt не закрывает нужный раздел.
Структурные данные (`json`, `api`, `rss`) отдают 17 источников, из них реально используются в коллекторах 3 сайта (`afisha`, `mosbilet`, `club16tons`) и API KudaGo и Timepad.
Ещё 45 адресов проверены, но не вошли в реестр (хост не ответил из нашего окружения, 404, заглушка или чужой сайт): список с причинами в `sources.json`, ключ `not_included`.

Таблица отсортирована по ценности для продукта: сначала то, что даёт много подтверждённых событий без ключа (рабочие коллекторы, затем
агрегаторы со структурными данными, затем остальные). Столбцы: «Ключ» — нужен ли токен или вход; «Статус» — код ответа и дата проверки (день.месяц, 2026);
«robots» — разрешён ли нашему боту адрес из ссылки (разбор по RFC 9309 с wildcard); «Условия» — что с условиями использования
(«прочитаны» — выводы в поле `legal` реестра; для остальных найденная ссылка записана там же, текст не изучен); «Свободно» — доступно без ключа сейчас.

Для Telegram добавить `TELEGRAM_PREVIEW_ENABLED=1` и `telegram` в `--sources`. Доля «подтверждено» после LLM-нормализации здесь не измерена: ключа
OpenRouter в окружении нет; в таблице выше приведён заменитель (карточки с датой, временем и площадкой в самом источнике).

Путь через MTProto (Telethon) остаётся заглушкой: `TelegramMtprotoCollector` и `TelegramCollector(mode="mtproto")` отвечают
`CollectorError` «нужны api_id/api_hash и вход». Нужны `api_id`/`api_hash` с my.telegram.org и вход под аккаунтом владельца.

Поправка к общему коду: стандартный `urllib.robotparser` ищет имя бота подстрокой и закрыл бы весь `bilet.mos.ru` (в его robots.txt есть группы
«Bot», «NE», «IS»), к тому же не знает `*` и `$` внутри пути. Поэтому в `_common.py` свой разбор `RobotsRules`. KudaGo при
`COLLECTORS_RESPECT_ROBOTS=1` по-прежнему использует стандартный разбор; при включении строгого режима его стоит перевести на `RobotsGuard`.

## Что решает владелец

1. **Telegram.** Включить сбор через публичное превью (`TELEGRAM_PREVIEW_ENABLED=1`) или нет. Условия Telegram (`telegram.org/tos`, `tos/content-licensing`)
   запрещают scraping и агрегацию данных для ИИ и ограничивают доступ к пользовательскому контенту «обычным, законным и предусмотренным использованием».
   robots.txt у `t.me` нет (404), но юридически вопрос открыт. Альтернатива: `api_id`/`api_hash` и вход под аккаунтом (Telethon), тоже в пределах тех же условий.
2. **Афиша (`afisha.ru`).** Условия использования, п. 3.3: «Сервис предназначен для личного некоммерческого использования». О сборе данных там ничего нет.
   Сбор идёт по решению от 24.10.2026 (агрегаторы на MVP бесплатно), риск остаётся осознанным; до монетизации желательно письмо в Афишу.
3. **Мосбилет (`bilet.mos.ru`).** Условий использования на сайте не нашли. Для полного горизонта (сейчас 12 ближайших событий на раздел) нужен официальный
   канал: API или выгрузка у оператора, либо `data.mos.ru` (ключ; хост из нашего окружения не отвечал).
4. **KudaGo и Timepad.** KudaGo: запуск с сервера, который он пускает (из нашего окружения 403). Timepad: токен `TIMEPAD_TOKEN`.
5. **Яндекс Афиша, Ticketland, Музей Москвы, Wine Street, Нетология и ТПП РФ отвечают 403, Большой театр 401** (защита): обход не делаем; нужен партнёрский доступ или отказ от источника.
6. **«Закрытые клубы»** не публикуют афишу открыто: источника в реестре нет, только ручной ввод или подача организаторов. «Бизнес-завтраки»: единственный
   кандидат в реестре (`amr.ru`) не проверен глубже главной страницы.
7. **API Культура.РФ и data.mos.ru**: хосты обрывали соединение из нашего окружения; проверить с сервера и получить ключи.
8. **Новые коллекторы читают robots.txt всегда**, независимо от `COLLECTORS_RESPECT_ROBOTS` (он относится к KudaGo). Подтвердить такой режим или ослабить.

## Решения по доступу

1. **robots.txt.** Все новые HTML-коллекторы (`afisha`, `mosbilet`, `club16tons`, `telegram`) читают robots.txt при каждом запуске и
   пропускают закрытые страницы независимо от `COLLECTORS_RESPECT_ROBOTS`: параметр конструктора `respect_robots` по умолчанию `True`, настройка
   `settings` ими не читается. Переменная относится только к KudaGo (решение владельца от 24.10.2026).
2. **Telegram.** Превью `t.me/s/` выключено по умолчанию (`TELEGRAM_PREVIEW_ENABLED=0`). Включает только владелец, после получения
   `api_id`/`api_hash` и решения по условиям Telegram. Выключенный коллектор виден в сводке запуска с причиной.
3. **MVP без соглашений.** По решению владельца на стадии MVP Афишу, Мосбилет и агрегаторы собираем бесплатно и без соглашений, чтобы проверить
   спрос; соглашения заключаем после подтверждения спроса. **Риск:** условия использования площадок (у Афиши «личное некоммерческое использование»,
   у Мосбилета условий не нашли) и возможные блокировки по IP (KudaGo и Яндекс Афиша уже отвечают 403). **Отключение:** при первом требовании
   правообладателя источник убирается из `--sources` в команде запуска воркера (настройка сервера, код и деплой не нужны); Telegram — ещё и
   `TELEGRAM_PREVIEW_ENABLED=0`. Отдельного флага «отключить источник» в коде нет, а запуск без `--sources` собирает все зарегистрированные
   коллекторы, поэтому на сервере `--sources` должен быть задан явно.

### Ждём владельца

- Лицензия KudaGo (передача данных третьим лицам запрещена, нужна индексируемая ссылка) и запуск сбора с адреса, который KudaGo пускает.
- Токен Timepad (`TIMEPAD_TOKEN`).
- Юридическая сторона Афиши (п. 3.3 условий) и Мосбилета (условий нет; нужен официальный API или выгрузка для полного горизонта).
- Telegram: `api_id`/`api_hash` и решение по условиям Telegram.
- Остальное из списка выше («Что решает владелец»): партнёрский доступ к сайтам с 403, ключи data.mos.ru и Культура.РФ, источники для «Закрытых клубов».

## KudaGo: что важно знать

- **robots.txt.** Для `User-agent: *` там `Disallow: /public-api`, хотя API опубликован для разработчиков. Учёт robots.txt
  включается переменной `COLLECTORS_RESPECT_ROBOTS=1`; по умолчанию 0 (решение владельца, см. «Решение по агрегаторам»).
  При 1 коллектор останавливается с ошибкой, не сделав ни одного запроса к API. Явный аргумент конструктора
  `KudaGoCollector(respect_robots=...)` сильнее настройки.
- **Доступ.** Из окружения разработки `/public-api/` отвечает 403 от nginx KudaGo даже с честным User-Agent
  (`robots.txt` и `docs.kudago.com` при этом открываются). Похоже на блокировку по адресу; обход не делали.
- **Лицензия** (раздел «Лицензионное соглашение» в документации; на MVP сбор бесплатный, соглашение — позже): у каждого показанного события должна быть прямая
  индексируемая ссылка на карточку первоисточника (кладём её в `RawEvent.url`), данные нельзя передавать
  третьим лицам на коммерческой основе, «kudago» нельзя использовать в названии продукта. Сверить с монетизацией (п. 9).
- **Не проверено на живом ответе:** смысл `actual_since` / `actual_until` в документации описан двусмысленно
  (начались после / закончились до), поэтому пересечение с диапазоном дополнительно проверяется у нас; значения
  дат «бессрочно» разбираются по флагам `is_endless` / `is_startless`.

## Что мешает прямо сейчас

- **KudaGo.** Из нашего окружения `/public-api/` отвечает 403 от nginx KudaGo (похоже на блокировку по адресу). Запрет в
  robots.txt владелец снял (учёт выключен по умолчанию), блокировку по адресу не обходим: сбор запускают с рабочего сервера.
- **Timepad.** Коллектор готов, нужен токен API в `TIMEPAD_TOKEN`: без него 403. Токен получает владелец.
- **Telegram.** Коллектор по превью готов, но выключен до решения владельца; MTProto требует `api_id`/`api_hash` и входа.
- **Яндекс Афиша, Ticketland.** Отвечают 403 (защита), обход запрещён.
- **Площадки (ГЭС-2, Гараж, ММОМА, МАММ, Зотов), джаз-клубы, Сколково/ВШЭ, `marielaveau.bar`.** Коллекторов
  ещё нет: парсер на каждый сайт, ничего внешнего не нужно. Часть площадок есть в Telegram-списке.
- **Большинство остальных сайтов реестра** (театры, музеи, билетные операторы) отдают только вёрстку: следующий шаг — по таблице сверху вниз,
  начиная с `kassir`, `concert_ru`, `gorodzovet`, `leaderid`.

## Решение по агрегаторам

**24.10.2026, владелец продукта.** На MVP собираем данные агрегаторов (KudaGo, Timepad и подобных) бесплатно, чтобы
проверить спрос. Соглашения с ними заключим, когда спрос подтвердится: до того момента лицензионные условия не
оформлены, и это осознанный риск.

- **Ссылка на первоисточник обязательна.** В каждой карточке остаётся `url` (из `RawEvent.url` в `EventIn.url` и `sources`),
  карточки её показывают. Коллектор пропускает событие без адреса первоисточника. При слиянии дубликатов конвейер
  переносит ссылки отброшенных карточек в `sources` оставленной.
- **Технические блокировки не обходим.** Если источник отвечает 403 по адресу, сбор запускают с рабочего сервера.
- **Учёт robots.txt** управляется `COLLECTORS_RESPECT_ROBOTS` (по умолчанию 0). Вернуть строгий режим можно
  одной переменной, код менять не нужно.
- **Пересмотр:** когда спрос подтвердится, оформить соглашения (у KudaGo лицензия запрещает передавать данные третьим
  лицам на коммерческой основе и требует индексируемую ссылку), затем вернуть `COLLECTORS_RESPECT_ROBOTS=1`,
  если источник того требует.

## Конвейер сбора на сервере

```bash
cd <корень репозитория> && . .venv/bin/activate
export DATABASE_URL=...          # база, куда писать черновики (по умолчанию локальная из settings.py)
export OPENROUTER_KEY=...        # LLM-нормализация; без ключа конвейер сам уйдёт в сухой прогон
export TIMEPAD_TOKEN=...         # токен Timepad; без него Timepad попадёт в сводку как «молчит»
export COLLECTORS_RESPECT_ROBOTS=0   # 0 — не читать robots.txt (решение владельца), 1 — читать и уважать
python -m leisure.collectors.pipeline --city Москва --days 14 --sources kudago,timepad --dry-run   # проверка без LLM и базы
python -m leisure.collectors.pipeline --city Москва --days 14                                       # боевой запуск
```

Те же переменные можно положить в `leisure/.env` (шаблон — `.env.example`). Опции: `--sources` (по умолчанию все
зарегистрированные), `--start YYYY-MM-DD` (по умолчанию сегодня по Москве), `--max-cards N` (потолок вызовов LLM за
запуск, защита расходов), `--raw-dir`.

Что делает боевой запуск: собирает источники (молчащий не мешает остальным), сохраняет сырые карточки в
`leisure/data/raw/*.json` (в git не попадают), отправляет в LLM только карточки, адреса которых ещё нет в базе,
убирает дубликаты между новыми и против событий базы за тот же диапазон (draft и published; событие из базы всегда
побеждает), записывает новые черновики через `seed.load.upsert_events` и печатает сводку: по источникам собрано,
уже в базе, ошибок LLM, дубликатов, черновиков, а также какие источники молчат и почему. Код выхода 1, если запись в
базу не удалась или молчат все источники. Куратор публикует черновики в админке.

## Запуск из кода

```python
from datetime import date
from leisure.collectors import load_collectors
from leisure.collectors.base import collect_all

load_collectors()  # импортирует модули-источники, срабатывают декораторы @register
events, sources = collect_all("Москва", date(2026, 10, 23), date(2026, 10, 25), names=["kudago"])
for r in sources:  # SourceReport: source, ok, count, error, seconds, stats
    print(r.source, "ok" if r.ok else f"молчит: {r.error}", r.count)
```

`collect_all` возвращает `CollectResult(events, sources)`: события всех источников, которые ответили, и по одной
записи `SourceReport` на каждый запущенный источник. Сбой одного источника (`CollectorError` или любое другое
исключение) пишется в лог с именем источника и не мешает остальным; причина попадает в `SourceReport.error`,
`result.failed` — только молчащие. Запрошенный в `names`, но незарегистрированный источник тоже виден в сводке.
Счётчики запуска (страниц, получено, оставлено, вне диапазона, пропущено, повторов) лежат в `SourceReport.stats`.

Структурные поля `RawEvent` (`address`, `metro`, `lat`, `lon`, `age_restriction`, `categories`, `place_name`)
необязательны: коллектор заполняет, что источник отдаёт отдельно от текста. Пустые поля в промпт нормализатора
не попадают.
