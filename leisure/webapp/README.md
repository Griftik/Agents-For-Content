# Catch · приложение (PWA, Next.js)

Catch (в речи «Кэтч»; слоган «Ничего интересного мимо тебя не пройдёт») — отдельное веб-приложение, которое ставится на экран
телефона (`leisure/docs/PIVOT-PWA.md`, версия 2): живая лента рекомендаций на сегодня, завтра, неделю; план; несколько профилей
в одном аккаунте. Telegram, бот, Mini App, push и «Входящие» сняты.
Next.js 15 (App Router, TypeScript), без Tailwind: токены и компоненты в `src/app/globals.css` — из `leisure/web/DESIGN.md`.
Экраны и тексты — `leisure/web/FLOW-APP.md`, `FLOW-ONBOARDING.md`, `FLOW-INVITE.md`, `COPY.md`.

## Экраны

| Маршрут | Что | Рендер |
|---|---|---|
| `/` | первый экран: нет сессии — гостевой аккаунт создаётся сам; нет согласия — приветствие (служебная строка CATCH, слоган, согласие, «Начать»); профиль не настроен — онбординг; иначе лента. `/?ref=<код>` → `/r/<код>` | сервер |
| `/digest?day=&seg=` | **Рекомендации**: дни (Сегодня · Завтра · Послезавтра · Неделя · дата), направление (Досуг · Дело · Всё), лента крупных карточек из `GET /api/feed` с бейджем «Успеваешь», «Иду» / «Не моё» кнопками и свайпом, «Отменить» 5 с, лист «В плане» → «К билетам», «Позвать друга» | сервер + клиентская колода; без JS видна первая карточка и «Подробнее» |
| `/plan` | **План**: секция «Прошли» с «Сходил / Не сходил» и ★1–5 (момент рекомендации после 4–5 приходит от API), дни недели, «Вдвоём с Имя», календари, «Позвать друга», «Убрать» | сервер + клиентские отметки |
| `/profile` | **Профиль**: переключатель профилей (я · мама · ребёнок · +) в шапке, имя, пять ценностей чипами по группам, направления 0–3 ползунками, бюджет, время, «На дорогу» 10–90 мин, «Что я о тебе узнал» (+/− чипы → Больше · Меньше · Сбросить), «Показывать имя друзьям», почта, «Удалить мои данные» | сервер + форма (PUT) |
| `/profile?onboarding=welcome\|1\|2` | первый вход: согласие и имя → «Шаг 1 / 2» пять ценностей со старта пустого выбора, все чипы активны, пятая сразу открывает шаг 2, черновик выбора переживает перезагрузку (sessionStorage) → «Шаг 2 / 2» восемь направлений и бюджет → лента на сегодня; кнопки форм блокируются на время запроса | сервер + форма |
| `/e/<slug>` | страница события: обложка, факты, описание, «К билетам» (источник), «Позвать друга»; без сессии — «Начать» | сервер, без входа |
| `/e/<slug>?inv=<код>` | приглашение: «Имя зовёт тебя», галочка согласия, «Иду вместе» / «Может быть» / «Другие события под меня», экран «Вы идёте вместе», статусы past / unpublished / gone; неизвестный код — явный экран «Эта ссылка не работает» с кнопкой «К событию» | сервер + клиентский блок |
| `/r/<код>` | ссылка-рекомендация: код проверяется в API и кладётся в cookie на 14 дней, затем приветствие; битый код — приветствие с пометкой «Ссылка не работает»; код приглашения на событие → его страница | route handler |
| `/policy` | политика из `leisure/web/POLICY.md` (копируется в `content/policy.md` перед `dev`/`build`) | сервер |
| `/api/session` | гостевая сессия: `POST /api/session` у API → подписанный httpOnly-cookie на 180 дней | route handler |
| `/api/events/<slug>/ics?day=` | файл календаря (прокси к API) | route handler |
| `/manifest.webmanifest`, `/sw.js`, `/offline.html`, `/icons/*` | PWA: манифест, service worker (только офлайн-заглушка), иконки | статика |

Нижняя навигация из трёх вкладок (`BottomNav`): Лента · План · Профиль; точка на «Плане», пока есть прошедшие «иду» без отметки.
Онбординг, приглашение и страница события идут без неё.

Шрифты (Piazzolla 800, Golos Text 400/500/600, IBM Plex Mono 500, latin + cyrillic) лежат в `public/fonts` и подключаются
`/fonts/fonts.css`: запросов к Google Fonts нет, service worker кэширует их вместе с офлайн-заглушкой.

## Вход и профили

Логинов нет. При первом визите `SessionBoot` вызывает `POST /api/session` веба, тот просит `user_id` у API и ставит cookie
`leisure_session` (`<id>.<exp>.<HMAC>`, 180 дней, `httpOnly`, `SameSite=Lax`, `Secure` в production). До галочки согласия на
приветствии профиль не создаётся. Все запросы к API делает сервер Next.js с `X-API-Key`.

Профили аккаунта: `GET/POST /api/profiles`; основной профиль «я» = сам аккаунт (`profile_id = user_id`). Активный профиль хранится
в подписанном cookie `leisure_profile` (`<profile_id>.<account_id>.<HMAC>`, `issueProfile` / `readProfile`); переключение проверяет
на сервере, что профиль принадлежит аккаунту. Лента, план, решения, приглашения и сам профиль работают от активного профиля
(`getProfileId`), сессия, список профилей, почта и удаление — от аккаунта (`getUserId`).

Режим разработки (`NODE_ENV=development`): `?dev_user=<id>` без подписи ставит dev-cookie. В production выключено.

## Переменные окружения

| Переменная | Нужна | Что |
|---|---|---|
| `API_BASE_URL` | да | адрес FastAPI, например `http://localhost:8000` (в compose `http://api:8000`) |
| `API_KEY` | да | значение `API_KEY` из окружения API; уходит заголовком `X-API-Key` только с сервера |
| `SESSION_SECRET` | да | секрет подписи cookie сессии и профиля; без него сессии не выдаются (в dev работает `?dev_user=`) |
| `WEB_BASE_URL` | нет | публичный адрес приложения для ссылок приглашений; без неё берётся из заголовков запроса |
| `MOCK_INVITES` | нет | `1` — мок-режим (см. ниже); только `npm run dev` и тесты |
| `MOCK_SMTP` | нет | `1` — мок почты отвечает «отправлено» вместо 503 |
| `MOCK_FORCE` | нет | `1` вместе с `MOCK_INVITES=1` включает мок и в production-сборке: только для скриншотов `npm run start`, не для сервера |

Шаблон: `.env.example`.

## Локальный запуск

```bash
# 1. API (из корня репозитория)
. .venv/bin/activate && API_KEY=dev-key ADMIN_PASSWORD= uvicorn leisure.api.main:app --port 8000

# 2. Приложение (из leisure/webapp)
npm install
cp .env.example .env.local        # впиши SESSION_SECRET
npm run dev                       # http://localhost:3000/  → приветствие → два шага → лента
```

Проверки: `npm run lint`, `npm test` (vitest: токены сессии и профиля, лента и «успеваешь», правила установки на экран,
онбординг, план, мок и серверные действия), `npm run typecheck`, `npm run build`. Иконки пересобираются `node scripts/make-icons.mjs`;
скриншоты экранов — `node scripts/shots.js` на production-сборке (см. «Сверка с дизайн-системой»; Playwright, папка `shots/`).

## Мок-режим `MOCK_INVITES=1`

Только при `NODE_ENV=development` (`npm run dev`) и `test`; в `next build` и `next start` игнорируется (`mockEnabled()` в `src/lib/mock.ts`).
Подмена на уровне `src/lib/api.ts`, ответы в памяти процесса. Мок отвечает на сессию, профили аккаунта, ленту (события с датами
относительно сегодня, «Дело» = четыре бизнес-категории, «успеваешь» по времени на дорогу), события, профиль, решения
(«иду», «не моё», «сходил», «не сходил», оценка → `ref_ask`), план, приглашения, почту (503 без `MOCK_SMTP`), удаление.

```bash
MOCK_INVITES=1 SESSION_SECRET=dev npm run dev
```

| Что открыть | Что видно |
|---|---|
| `/` | гостевая сессия создаётся сама → приветствие → Шаг 1 → Шаг 2 → лента |
| `/digest?dev_user=1001` | готовый профиль «Мария»: лента на сегодня; `&day=week&seg=business` — неделя, «Дело» |
| `/plan?dev_user=1001` | «Прошли»: органный вечер с «Сходил / Не сходил» и звёздами; оценка 5 даёт «Поделиться» |
| `/profile?dev_user=1001` | профиль v2; чип «Мария» в шапке → лист профилей → «+ Новый профиль» |
| `/profile?onboarding=welcome&dev_user=7001` | первый вход с нуля |
| `/e/karmannyj-ongon?inv=MOCKOK01&dev_user=2002` | приглашение без согласия: галочка, «Иду вместе» |
| `MOCKANON`, `MOCKPAST`, `MOCKUNPB`, `MOCKGONE`, `/e/-?inv=NOPE0000` | имя скрыто; прошло; снято; пригласивший удалил профиль; ссылка не работает |

## PWA

- `src/app/manifest.ts`: `name` / `short_name` `Catch`, `display: standalone`, `orientation: portrait`, цвета `--bg` обеих тем,
  иконки 192/512 и maskable (`public/icons`, рисуются `scripts/make-icons.mjs`: пока буква C акцентом на фоне светлой темы;
  окончательный знак опишет дизайн).
- `public/sw.js`: кэширует только `/offline.html` и иконку; навигация идёт в сеть, без сети — заглушка. Данные не кэшируются.
  Push-обработчиков нет (сняты в версии 2). `next.config.ts` отдаёт `/sw.js` с `no-store`, чтобы обновления не застревали.
- `PwaBoot` регистрирует SW и показывает мягкий баннер «Установить на экран» по правилам `src/lib/install.ts`: не раньше второго
  визита или первого «Иду», не в установленном приложении, после «Не сейчас» молчит 14 дней, после третьего отказа насовсем;
  Android/Chrome — системный диалог по `beforeinstallprompt`, iOS Safari — три шага через «Поделиться», другие браузеры iOS —
  «открой в Safari». Счётчики лежат в `localStorage` (удобство одного устройства).

## Приглашения

Постановка — `leisure/docs/GROWTH.md`, экраны — `web/FLOW-INVITE.md`. Ссылка одна: `<WEB_BASE_URL>/e/<slug>?inv=<код>`
(`web_url` из `POST /api/invites`; `url` там null и не используется). «Позвать друга» (`InviteButton`) создаёт приглашение
server action'ом и открывает нижний лист: «Поделиться» — Web Share API, «Скопировать» — запасной вариант. На странице приглашения
галочка согласия стоит заранее, пока `profile.has_consent` не true; выбор запоминается и записывается на втором из двух нажатий
(галочка и кнопка в любом порядке), отдельного «подтвердить» нет. Имя — необязательное поле на той же странице (пригласивший увидит
«Друг идёт с тобой», если оно пустое). «Другие события под меня» шлёт `declined`. Повтор предложения своей подборки — по `profile.offer_due`.

Нажатия приглашённого до записанного «иду» (`src/lib/invite.ts`, тест): ссылка 1 + галочка 1 + «Иду вместе» 1 = **3** (на странице 2);
с согласием — 2. Отдельного шага входа нет: гостевая сессия создаётся сама.

## API v2 и сквозная проверка

Контракт — `leisure/README.md`, раздел «Продукт без Telegram (версия 2)». Что использует веб:

| Вызов | Как | Где |
|---|---|---|
| `POST /api/session` → `{user_id}` (с 10¹²) | route `/api/session` подписывает cookie | `SessionBoot` |
| `PUT /api/profile/{id}` с `consent`, `name`, `values`, `interests`, `params.budget` / `travel_minutes`, `onboarded`, `affinity`, `show_name`, `offer_seen`, `ref_code` | server actions | онбординг, профиль |
| `GET /api/profiles?user_id=` → `{account_id, email, profiles: [{user_id, name, kind, onboarded, is_main}]}`; `POST /api/profiles {user_id, name, kind}` → тот же список (нужно согласие, до шести) | новый профиль — тот, которого не было в списке | `ProfileSwitcher`, `createProfileAction` |
| `GET /api/feed?user_id=&date=today\|tomorrow\|week\|YYYY-MM-DD&segment=leisure\|business\|all&limit=` → `{days, today, travel_minutes, items: [{event, day, days, score, can_make_it, links}]}`; 409 `not_onboarded` → онбординг | «Послезавтра» уходит датой | `/digest` |
| `POST /api/decisions` со статусами `иду`, `не моё`, `сходил`, `не сходил` и `rating`; ответ с `ref_ask {url, share_text}` (оценка 4–5, раз в 14 дней) и `ask_reason`; «сходил» раньше дня события — 400 | `feedDecideAction`, `markPastAction` | лента, план |
| `GET /api/plan/{id}` → `weekend` (7 дат от сегодня), `today`, `days`, `horizon`, `past` (30 дней, с `rating` и `companions`) | «Прошли» и точка на вкладке — из `past` | `/plan` |
| `POST /api/invites`, `GET /api/invites/{code}`, `/open`, `/accept` (`going` / `maybe` / `declined`, `consent`, `name`) | ссылка — `web_url` на `WEB_BASE_URL` | приглашения |
| `POST /api/auth/email` → 503 без SMTP («почта пока не подключена»); `GET /api/auth/email/{token}` → `{user_id, account_id, email, moved}` | страница перехода по ссылке из письма пока не сделана (SMTP нет) | профиль |
| `DELETE /api/profile/{id}` — у основного профиля стирает аккаунт целиком | `deleteDataAction` | профиль |

Сквозной прогон без браузера — `scripts/e2e-v2.mjs`: настоящий FastAPI и production-сборка веба без мока; server actions
вызываются теми же запросами, что шлёт браузер (ид из `.next/server/server-reference-manifest.js`, FormData как у `encodeReply`).

```bash
# 1. API (из корня репозитория; база поднята, seed загружен)
LEISURE_DEV_OPEN_API=1 WEB_BASE_URL=http://localhost:3111 .venv/bin/uvicorn leisure.api.main:app --port 8000 &
# 2. Production-сборка веба без мока (из leisure/webapp)
npm run build && API_BASE_URL=http://localhost:8000 SESSION_SECRET=e2e-secret WEB_BASE_URL=http://localhost:3111 npx next start -p 3111 &
# 3. Прогон (тестовые аккаунты создаются и удаляются сами)
node scripts/e2e-v2.mjs
```

Результат на 25.10.2026 на настоящих событиях (seed): **60 проверок из 60**. Путь: сессия (cookie 180 дней,
`user_id ≥ 10¹²`) → `/` ведёт на приветствие, профиля в API нет → «Начать» с галочкой создаёт профиль (`has_consent`,
`account_id = user_id`, `kind self`) → лента до онбординга 409 → Шаг 1 (пять ценностей) → Шаг 2 (направления, бюджет 2500) →
лента: сегодня все на сегодня; неделя — окно из 7 дней; «Дело» — только бизнес-категории (в seed их нет → «Пока ничего» и
кнопка «Всё»); веб показывает первую карточку API со счётчиком, бейдж «Успеваешь» совпадает с `can_make_it` → «Иду» и «Не моё»,
«Отменить» возвращает событие в ленту, повторное «не моё» убирает → «Убрать» в плане снимает решение → «Что я о тебе узнал»:
Больше → +1, Сбросить → 0 → план на 7 дней с «иду» → вчерашнее «иду» (через API) → «Прошли», чипы, точка на вкладке → «сходил» на
завтрашнее — отказ → «Сходил» + 5 → `ref_ask`, `past` с `rating 5`, `● 5 ★`, точка погасла → профиль «Мама» (cookie профиля подписан,
шаг 1 «Что важно для Мама», свои ценности, тот же аккаунт) → лента «Мамы» отличается от основной → обратно на «я», чужой id не
переключает → «Позвать друга»: код и обычная ссылка → битый код на событии — «Эта ссылка не работает» и «К событию», битый `/r/` —
приветствие с пометкой → страница без сессии с галочкой и «Иду вместе» → друг без галочки не записан, с галочкой «Вы идёте вместе»,
профиль друга `source invite` с именем с формы → у пригласившего `companions = [Борис]` и «Вдвоём с Борис», у друга «Вдвоём с Вера»
→ почта без SMTP: «почта пока не подключена», API 503 → «Удалить мои данные» у друга и у основного аккаунта (вместе с «Мамой»):
профили 404, сессия сброшена, экран «Данные удалены».

### Правки по отчёту QA (`leisure/tests/e2e/REPORT.md`)

- Шаг 1 стартует с пустого выбора (демо-веса профиля по умолчанию не считаются выбором), все 19 чипов активны (без `disabled`,
  шестая просто не выбирается), счётчик `0 / 5`, «Дальше» только при пяти, черновик выбора живёт в `sessionStorage` до отправки.
- «Прошли» не пересортировывается после «Сходил»: `markPastAction` не перерисовывает план, порядок меняется при следующем заходе.
- `overflow-wrap: anywhere` у заголовков, мест, описаний и записей плана: слово из 102 букв больше не растягивает страницу.
- Ряд дней без затухания; выбранный чип («Неделя», дата из календаря) прокручивается в видимую зону, календарь закреплён справа.
- Чип профиля: инициал плюс имя, при пустом имени только инициал. Пояснительные абзацы сняты с приветствия, экрана «Вы идёте
  вместе» и переключателя имени (согласие с ссылкой на политику осталось). «Начать», «Показать рекомендации», «Иду вместе» и
  «Может быть» блокируются на время запроса. Битый код приглашения и битая ссылка-рекомендация — явные экраны.

## Сверка с дизайн-системой и чеклистами

Источник правды — `web/DESIGN.md` v2 (направление B «Билет»): Piazzolla 800 / Golos Text 400 / IBM Plex Mono 500 капслок (`.svc`),
один акцент, радиус 20, карточка-билет с линией отрыва (`.tear`), равные «Не моё» / «Иду» 56 px, нижняя навигация «Лента · План ·
Профиль» с точкой на «Плане», одно оркестрованное появление за запуск (`html[data-reveal]`, атрибут ставится инлайн-скриптом до
первой отрисовки, один раз на сессию вкладки) и микродвижение, всё выключается `prefers-reduced-motion`.

Скриншоты (`shots/`, Playwright, 390 × 844, обе темы: лента «Сегодня» и «Неделя · Дело», план и план с оценкой, профиль целиком,
переключатель профилей, три экрана онбординга, приглашение, событие, перетаскивание карточки со стампом, лист «В плане», тост
«Отменить»). Снимаются на production-сборке, чтобы в кадре было то, что увидит владелец (в dev Next рисует круглый значок «N» в углу), и с
настоящими событиями из API: скрипт сам создаёт через API готовый профиль с «иду» и вчерашним событием, черновик для шагов 1/2,
нового гостя и приглашение, а после удаляет их.

```bash
# API и production-сборка веба подняты, как в разделе «API v2 и сквозная проверка»
E2E_API=http://localhost:8000 SESSION_SECRET=e2e-secret node scripts/shots.js
# без API — на моке: MOCK_INVITES=1 MOCK_FORCE=1 у сервера веба и node scripts/shots.js
```

`MOCK_FORCE=1` — второй флаг, без которого мок в production-сборке игнорируется; только для скриншотов. Результат: горизонтального
скролла нет ни на одном экране (`scrollWidth = 390`), консоль без ошибок и предупреждений, индикатора dev-режима в production нет
(скрипт проверяет `nextjs-portal`), обрезанных текстов нет (ряд дней прокручивается намеренно, с затуханием у края, календарь
закреплён справа), читаемость в тёмной теме сохранена. Пустая зона билета между линией отрыва и подвалом заполнена описанием
события в две строки (или тегами, если описания нет).

Отступления от чеклистов навыков (`distinctive-frontend`, `app-design-101`, `mobile-app-ui-design`, `ux-designer`), осознанные:

- **distinctive-frontend: слоистый фон с текстурой.** Фон плоский по DESIGN.md (карточка — единственное пятно). Контраст весов
  800 / 400 и оркестрованное появление теперь есть, пункт снят.
- **mobile-app-ui-design: ≤ 2 семейства, тени, свечения, эмодзи в выборе, Tailwind / Lucide.** Три шрифтовые роли, строковые SVG,
  без теней (кроме перетаскиваемой карточки) — требование DESIGN.md; размеров 5 (служебный 11 обязателен).
- **ux-designer: звёздочка у обязательного поля, валидация на blur.** Единственное обязательное поле (имя нового профиля)
  помечено `required` без звёздочки — DESIGN.md без пояснений; почта проверяется сервером после отправки.
- **app-design-101, гл. 4 (серые макеты).** Структура проверена на скриншотах в цвете; отдельный серый прогон не делался —
  переключатель «Серая структура» есть в `web/mockup.html`.
- **DESIGN.md, не сделано:** обложка 16:9 показывается только при `cover` в ответе ленты (в модели события поля пока нет);
  «Установить на экран» в профиле как строки нет (общий баннер `PwaBoot`); «Прошли» показывает до 12 событий; `T-FEED-LATE`
  («Сегодня уже поздно») определяется по часу (после 20:00 при пустой ленте), а не по ответу API.
