# Досуг · Mini App (Next.js)

Веб-часть планировщика: Telegram Mini App, она же обычный сайт. Next.js 15 (App Router, TypeScript), без Tailwind:
токены и компоненты в `src/app/globals.css` взяты из `leisure/web/DESIGN.md` и макета `leisure/web/mockup.html`.

## Страницы

| Маршрут | Что | Рендер |
|---|---|---|
| `/digest` | 5 слотов рекомендации + полный список с фильтрами (день, направление, бесплатно, скрыть «мимо») | сервер, читается без JS |
| `/plan` | три колонки по дням, конфликты, календари, «На горизонте», «Скопировать план» | сервер; JS нужен только для копирования |
| `/profile` | ценности, направления, параметры, «Что я узнал о тебе», заметка | сервер + форма (PUT); JS только для живого числа у ползунков |
| `/e/<slug>` | публичная страница события, кнопка «Собрать мне такую подборку» → `t.me/<бот>?start=e_<slug>`; после «Иду» — «Позвать друга» | сервер, без входа |
| `/e/<slug>?inv=<код>` | страница приглашения: шапка «Имя зовёт тебя», карточка, «Иду вместе» / «Может быть» / «Другие выходные под меня»; экран «Вы идёте вместе»; экраны past / unpublished / gone / «ссылка не работает» | сервер + клиентский блок действий |
| `/profile?onboarding=welcome\|1\|2` | онбординг в Mini App: приветствие и согласие, «1 из 2» пять ценностей из 19 в четырёх группах, «2 из 2» восемь направлений и бюджет | сервер + форма |
| `/policy` | политика из `leisure/web/POLICY.md` (копируется в `content/policy.md` перед `dev`/`build`) | сервер |
| `/api/events/<slug>/ics?day=` | файл календаря (прокси к API) | route handler |
| `/api/auth/telegram` | обмен initData на cookie сессии (и cookie с именем из Telegram для записи приглашённого) | route handler |
| `/api/invite/<код>` | для клиентского слоя: слаг события по коду из `start_param` (прокси к `GET /api/invites/{код}`) | route handler |
| `/api/ref` | сохраняет код `ref_<код>` в cookie | route handler |

Кнопки решений («Иду», «Может быть», «Интересно», «Мимо», причины, день, «Убрать») — обычные `<form>` с server actions:
работают без JS (страница перезагружается), с JS — без перезагрузки.

## Вход

Логинов нет. Mini App получает `initData` от Telegram; клиентский слой (`TelegramBoot`) отправляет его в заголовке
`X-Telegram-Init-Data` на `/api/auth/telegram`. Сервер проверяет подпись HMAC-SHA256 (секрет = `HMAC_SHA256("WebAppData", токен бота)`),
свежесть `auth_date` (не старше суток) и достаёт `user.id`, затем выдаёт подписанный httpOnly-cookie на сутки
(`SameSite=None; Secure; Partitioned` в production, так как в вебе Telegram приложение живёт во фрейме).
Все запросы к API делает только сервер Next.js с `X-API-Key`; ключ в браузер не попадает.

Режим разработки (`NODE_ENV=development`, то есть `npm run dev`): `?dev_user=<telegram id>` без подписи ставит dev-cookie.
В production этот путь выключен и dev-cookie не принимается.

## Переменные окружения

| Переменная | Нужна | Что |
|---|---|---|
| `API_BASE_URL` | да | адрес FastAPI, например `http://localhost:8000` (в compose `http://api:8000`) |
| `API_KEY` | да | значение `API_KEY` из окружения API; уходит заголовком `X-API-Key` только с сервера |
| `LEISURE_BOT_TOKEN` | да | токен бота: проверка подписи initData |
| `NEXT_PUBLIC_BOT_USERNAME` | да | имя бота без `@` для ссылок `t.me/<бот>`; читается на старте, пересборка не нужна |
| `WEB_BASE_URL` | нет | публичный адрес веба для ссылок «Другу»; без неё берётся из заголовков запроса |
| `NEXT_PUBLIC_MINIAPP_SHORT_NAME` | для приглашений | короткое имя Mini App из BotFather: ссылка приглашения `https://t.me/<бот>/<app>?startapp=inv_<код>`; без него — `https://t.me/<бот>?startapp=…` (главное приложение бота). Читается на старте |
| `SESSION_SECRET` | нет | секрет подписи cookie; без него выводится из токена бота |
| `MOCK_INVITES` | нет | `1` включает мок-режим (см. ниже); только `npm run dev` и тесты |

Шаблон: `.env.example`.

## Локальный запуск

```bash
# 1. API (из корня репозитория)
. .venv/bin/activate && API_KEY=dev-key ADMIN_PASSWORD= uvicorn leisure.api.main:app --port 8000

# 2. Веб (из leisure/webapp)
npm install
cp .env.example .env.local        # впиши LEISURE_BOT_TOKEN и имя бота
npm run dev                       # http://localhost:3000/digest?dev_user=<telegram id>
```

Профиль пользователя создаётся в боте (`/start`) или первым `PUT /api/profile/<id>`; без него страницы покажут экран «Сначала познакомимся».
Для проверки на данных октября 2026 в dev можно добавить `?today=2026-10-23`.

Проверки: `npm run lint`, `npm test` (vitest: подпись initData, сессия, разбор `start_param`, подсчёт нажатий приглашённого, текст приглашения, адаптер ответов API, мок и серверные действия приглашений), `npm run typecheck`, `npm run build`.

## Docker

Сервис `web` описан в `leisure/docker-compose.yml` (порт 3000). Контекст сборки — `leisure/` (нужен `web/POLICY.md`):

```bash
cd leisure && docker compose up -d --build web
```

В `leisure/.env` должны быть `API_KEY`, `LEISURE_BOT_TOKEN`, `NEXT_PUBLIC_BOT_USERNAME`; `WEB_BASE_URL` для API и веба должен
указывать на публичный адрес веба (HTTPS), а не на порт API.

## Устройство

- `src/lib/telegram.ts` — проверка initData; `session-token.ts` — cookie сессии; `session.ts` — чтение сессии на сервере.
- `src/lib/api.ts` — клиент API (только сервер, `import "server-only"`).
- `src/app/actions.ts` — server actions: решения, «Убрать», сохранение профиля.
- `src/middleware.ts` — только `?dev_user` в режиме разработки.
- Цвета текста `warn` и `brass` в светлой теме затемнены (`--warn-ink`, `--brass-ink`): токены DESIGN.md дают там 4.40 и 3.96:1.

## Приглашения в Mini App

Постановка — `leisure/docs/GROWTH.md` (разделы 2, 4, 6), экраны — `leisure/web/FLOW-INVITE.md`, тексты — `leisure/web/COPY.md`, раздел 9 (`T-INVITE-*`, `T-REF-*`, `T-SETUP-NAME`).

### Как это работает

- **`start_param`** (`TelegramBoot`, `src/lib/start-param.ts`). Читается из `initData.start_param`, `initDataUnsafe`, хеша `tgWebAppStartParam` или запроса. `inv_<код>` → клиент спрашивает `/api/invite/<код>` (слаг из `GET /api/invites/{код}`) и делает `router.replace('/e/<слаг>?inv=<код>')`; код не найден → `/e/-?inv=<код>`, страница покажет «Эта ссылка не работает». `ref_<код>` → `POST /api/ref` кладёт код в cookie `leisure_ref` (14 дней) и ведёт на `/profile?onboarding=welcome`; при первом касании профиля (кнопка «Начать») код уходит в `PUT /api/profile` полем `ref_code`, cookie очищается. Каждый `start_param` разбирается один раз за вкладку (флаг в sessionStorage), иначе перезагрузка возвращала бы на приглашение. Для проверки в браузере: `/digest?tgWebAppStartParam=inv_MOCKOK01&dev_user=2002` (мок-режим).
- **«Позвать друга»** (`InviteButton`). Показывается у события с решением «Иду» в `/digest` (карточка и слот) и на `/e/<slug>`, а в `/plan` — у каждой записи («Иду» и «Может быть»); до «Иду» остаётся прежняя ссылка «Другу». Нажатие → server action `createInviteAction` → `POST /api/invites` → окно (нижний лист) с текстом `share_text`. «Поделиться»: в Telegram `openTelegramLink` на `t.me/share/url?url=…&text=…`, иначе `navigator.share`; «Скопировать» — запасной вариант с подтверждением (`T-INVITE-COPIED`), главный, если «Поделиться» недоступно. Системный выбор чата открывается вторым нажатием, а не после ожидания сервера: Safari не пускает `navigator.share` без свежего жеста. Ссылка в тексте одна; для `share` она убирается из текста, чтобы не дублироваться в чате.
- **Страница приглашения** (`/e/[slug]?inv=`). Статус берётся из `GET /api/invites/{код}`, а не из слага. `active` — шапка, карточка, действия; `past`, `unpublished` — экран с выходом в «Дайджест» (или «Другие выходные под меня», если профиля нет); `gone` (пригласивший удалил профиль) — шапка «Тебя зовут на событие», кнопки «Иду» / «Может быть» без слова «вместе» (так в FLOW-INVITE, п. 7); код неизвестен — событие по слагу, если оно есть, иначе «Эта ссылка не работает». Имя `inviter_name = null` → «Друг зовёт тебя». Автор, открывший своё приглашение, видит `T-INVITE-SELF`. Прежний ответ друга — строкой «Прежний ответ: иду, суббота». Строка «Совпадение N %» и «Почему тебе» для друга с готовым профилем не сделана: в контракте §6 для неё нет данных.
- **Запись «иду»** (`InviteFlow` + `acceptInviteAction`). Галочка согласия стоит на странице заранее, пока профиля нет. «Иду вместе» и «Может быть» запоминают выбор; запись идёт, когда есть и сессия, и согласие, в любом порядке («сначала кнопка, потом галочка» показывает `T-INVITE-CONSENT-NEED` и фокусирует галочку). Отдельной кнопки «подтвердить» нет. `POST /api/invites/{код}/accept` получает `consent: true` при первом касании. Если сервер ответил `409 consent_required` (профиль-заготовка без согласия), галочка появляется и выбор записывается после неё. `410` → «событие недоступно».
- **«Вы идёте вместе»**. Название, день, время; кто увидит («Имя» или «Друг»); календари Google / Outlook / .ics (ссылки берутся из плана пользователя, `.ics` — всегда наш маршрут); «Получать план в Telegram» вызывает `Telegram.WebApp.requestWriteAccess` (SDK подгружается только по этому нажатию), при отказе всё работает; блок «Хочешь свою подборку на выходные? Два шага» → «Давай» (`/profile?onboarding=1`, согласие уже есть) / «Потом» (`T-INVITE-LATER`, cookie `leisure_offer` с днём события). При первом открытии Mini App после этого дня `layout.tsx` один раз показывает повтор («Давай» / «Не нужно», `LaterOffer`), если профиль не готов.
- **Браузер без Telegram**. Страница видна целиком, но вместо кнопок решения — `T-INVITE-BROWSER` и «Открыть в Telegram» на `https://t.me/<бот>/<app>?startapp=inv_<код>`; записать «иду» вне Telegram нельзя.
- **Онбординг в Mini App** (`/profile?onboarding=…`, `Onboarding.tsx`, `ValuePicker.tsx`). Приветствие (`T-REF-LANDING`, согласие только если профиля нет) → «Шаг 1 из 2»: пять ценностей из 19 по группам из `catalog.value_clusters` (выбранные = 5, остальные = 2; шестую выбрать нельзя; интересы на этом шаге не пишем, потому что `PUT` с `interests` помечает профиль готовым) → «Шаг 2 из 2»: восемь направлений (предложены по `catalog.category_values`, нажатие убирает), строка бюджета, «Показать подборку» (`interests`: первые пять — 3, ещё три — 2, снятые — 0, остальные — 1; `budget`; умолчания из `FLOW-ONBOARDING`; `onboarded: true`) → `/digest`. Готовый профиль с `?onboarding` сразу уходит в `/digest`.
- **Профиль**: переключатель «Показывать имя друзьям» (`role="switch"`, `PUT /api/profile/{id}` с `show_name`), по умолчанию включён.
- В `/plan` под временем стоит подпись «Вдвоём с Имя» / «С друзьями (n)» по полю `companions` плана (оно уже есть в схеме бэкенда).

### Число нажатий приглашённого до записанного «иду»

Считает `src/lib/invite.ts` (`inviteeTaps`), та же логика решает, показывать ли галочку; покрыто тестом.

| Путь | Нажатия |
|---|---|
| Mini App, согласия нет | **3**: ссылка 1, галочка 1, «Иду вместе» 1 (последние два в любом порядке; на самой странице 2) |
| Mini App, профиль уже есть | **2**: ссылка, «Иду вместе» |
| Браузер без Telegram (запасной путь) | 4: ссылка, «Открыть в Telegram», галочка, «Иду вместе» (запись только в Telegram) |

До первой собственной подборки после «Давай»: +1 «Давай», 5 ценностей, «Дальше», бюджет (0, если «Не важно» подходит), «Показать подборку».

### Мок-режим `MOCK_INVITES=1`

Только при `NODE_ENV=development` (`npm run dev`) и `test` (vitest); в `next build` и `next start` флаг игнорируется (`mockEnabled()` в `src/lib/mock.ts`). Подмена идёт на уровне `src/lib/api.ts`, ответы лежат в памяти процесса (сбрасываются перезапуском). Мок отвечает на каталог, событие, профиль, решения, дайджест, план и три маршрута приглашений.

```bash
MOCK_INVITES=1 npm run dev    # API и бот не нужны; остальные переменные из .env.example
```

### Что ждём от бэкенда (расхождения с `GROWTH.md` §6)

Веб написан по §6; `src/lib/invite-api.ts` дополнительно принимает форму текущего `api/schemas.py`, чтобы не ломаться, но договориться стоит:

1. `GET /api/invites/{code}`: в схеме сейчас `state` (`ok` / `event_gone` / `past`), в §6 и в дизайне — `status` (`active` / `past` / `unpublished` / `gone`). Нужен `status`; `gone` = пригласивший удалил профиль, событие доступно (сейчас бэкенд в этом случае отвечает 404 — веб покажет «ссылка не работает»). Для автора приглашения веб передаёт `?user_id=` и читает необязательное `inviter_is_me`.
2. `POST /api/invites`: §6 — `event_slug`, `day`, ответ `code`, `url`, `web_url`, `share_text`; сейчас поле называется `event`, а в ответе нет `url` и `share_text`, есть `bot_link` вида `?start=inv_…`. Веб шлёт оба имени поля, ссылку `startapp` собирает сам из `NEXT_PUBLIC_BOT_USERNAME` и `NEXT_PUBLIC_MINIAPP_SHORT_NAME`, текст — по `T-INVITE-SHARE`, если `share_text` нет. Нужны `url` и `share_text` от API.
3. `POST /api/invites/{code}/accept`: сессия передаётся полем `user_id` в теле (в §6 — заголовком сервера); веб дополнительно шлёт `name` и `username` из Telegram (имя нужно для «Имя идёт с тобой»; в §6 их нет). Ответ: `profile_state` и `together_with` вместо `companions` (адаптер понимает оба).
4. Профиль: `PUT /api/profile/{id}` должен принять поле кода рекомендации (веб шлёт `ref_code`; имя поля нужно согласовать) и записать `source = ref`, `referred_by`.
5. `GET /api/catalog` должен отдавать `category_values` (таблица «направление → ценности», `CATEGORY_VALUES` из `core/catalog.py`), иначе восемь направлений на шаге «2 из 2» выбираются по текущим интересам профиля, а не по ценностям. Ранжирование повторено в `src/lib/onboarding.ts` по `rank_categories`; `PROPOSED_N = 8` и `PROPOSED_TOP = 5` пока продублированы.
6. Нет API «приглашение отклонено» (`declined` для «Другие выходные под меня»): кнопка сейчас просто ведёт в «Дайджест» или на онбординг.
7. Вне зоны веба: в `leisure/docker-compose.yml` и `leisure/.env` нужна `NEXT_PUBLIC_MINIAPP_SHORT_NAME` для сервиса `web`.
