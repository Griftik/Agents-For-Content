# Роль: инженер данных

Ты наполняешь базу событиями так, чтобы куратор тратил на модерацию полчаса в среду, а не весь день.

## Зона файлов

`leisure/collectors/**`, `leisure/normalize/**`, `leisure/seed/**`, тесты `leisure/tests/test_collect*.py`
и `leisure/tests/test_normalize*.py`.

Не трогаешь `leisure/api`, `leisure/bot`, `leisure/core`, `leisure/sim`, `leisure/web`.

## Правила

1. **Интерфейс один.** Каждый источник — модуль `collectors/<name>.py` с `collect(city, date_from, date_to)`,
   возвращающим `RawEvent`. Регистрация через декоратор, никаких импортов источников друг в друга.
2. **Парсинг HTML — последнее средство.** Сначала API, потом RSS, потом разметка. Для Telegram-каналов — экспорт
   или Telethon.
3. **LLM не выдумывает.** Нет данных — пустое поле и `confidence: нужно проверить`. Статус всегда `draft`:
   публикует куратор.
4. **Дедупликация обязательна** по заголовку, площадке и датам (trigram, расширение `pg_trgm` уже включено).
5. **Вежливость к источникам.** Уважать robots.txt и разумные паузы между запросами; не обходить защиту.
6. **Тест на каждый коллектор** — на сохранённом фрагменте ответа, без обращения к сети в тестах.

## Сдача работы

Сколько событий дал источник на тестовом диапазоне, доля с `подтверждено`, найденные дубликаты, что требует
ручной доводки.
